# AgyPTC — Programmatic Tool Calling (Code Mode) Rules

Use **`mcp_agy-ptc_vm_exec`** (eagerly loaded native tool) to collapse multi-step search, AST inspection, data-dependent branching/loops, atomic multi-file edits, and fast verification into **ONE TypeScript program turn**.

## When to Use `mcp_agy-ptc_vm_exec` vs. Built-in Tools

| Scenario | Preferred Tool | Why |
| :--- | :--- | :--- |
| Read 1–3 known small files (`<300` lines) or known line slices | Built-in `read_file` (in parallel) | Locally allowlisted (~7ms, 46 KB/call inline) |
| **Any `>=2`-step or data-dependent chain** (search -> outline -> read -> filter -> edit -> fast verify), loops over files, or **`<15s` fast checks** (`go vet`, `tsc --noEmit`, lint, scoped unit tests) | **`mcp_agy-ptc_vm_exec`** (`{ cwd, code, payloads?, title?, timeoutMs?, maxOutputBytes? }`) | Runs locally in `<5ms` isolated TS VM (`20s` default / `120s` max timeout, process-tree kill); intermediate data stays in sandbox memory |
| Multi-file or multi-hunk edits + fast checks | **`mcp_agy-ptc_vm_exec`** with one `edit.apply`, then `sh.checks` | Every hunk is validated before any write; a failed check leaves the edits on disk, so the next turn sends only the fix |
| **Long-running tasks (`>15s`)**, full integration/E2E test suites, heavy builds (Gradle/Cargo/Docker), interactive commands, or **daemons (`IsDaemon: true`)** | Built-in **`run_command`** (`WaitMsBeforeAsync: 500..2000`) + **`manage_task`** | Detaches into `/tasks` with live streaming stdout, `send_input`/`kill` control, and automatic Reactive Wakeup without blocking the turn |
| Macro multi-agent fan-out across independent subsystems | Built-in `run_workflow` or `swarm` (instruct workers in `brief` to use `mcp_agy-ptc_vm_exec`) | Parallel LLM reasoning + PTC inside each worker |

## Sandbox API Quick Reference (`code` is an async TypeScript function body)

- **Paths**: Always pass workspace root in `cwd`. Relative paths resolve against `cwd`; **external absolute paths or `../` cross-repo paths** (`D:/OtherRepo/...`, `~/...`) are also supported across `fs.*`, `search.*`, `ast.*`, `edit.*`, `tx.*`, `git.*` (`{ cwd }`), and `sh.*` (`{ cwd }`).
- **Payloads (`P` / `payloads`)**: Put multiline replacement code or templates in top-level `payloads: { newFunc: "..." }` and reference `P.newFunc` inside `code` (avoids nested JSON string escaping).
- **`search`**:
  - `await search.rg(pattern, { path?, glob?, literal?, ignoreCase?, contextLines?, maxResults? })` -> `Array<{ file, line, column, text, match, before?, after? }>`; `{ filesOnly: true }` -> `string[]`, `{ count: true }` -> `{ [file]: n }`
  - `await search.glob(pattern, { path?, maxResults? })` -> `string[]` (use `*` and `{a,b}`, not regex `|`)
- **`ast`**:
  - `await ast.outline(path)` / `await ast.outlines(paths)` -> `{ file, totalLines, symbols: [{ kind, name, signature?, startLine, endLine }] }` (exact `go/parser` AST for Go; TS/JS/Py/Rust/C/C++/Kotlin/Java/MD supported)
  - `await ast.read(path, "Type::method")` -> `{ kind, name, startLine, endLine, text }` (also `Type.method`, bare `name`)
  - `await ast.enclosingSymbol(path, line)` -> `{ kind, name, startLine, endLine } | null`
- **`fs`**:
  - `await fs.read(path, { startLine?, endLine?, tail?, lineNumbers? })` -> `string` (up to 2 MB; `tail: N` = last N lines of any size file)
  - `await fs.cat(paths, opts?)` -> `{ [path]: text | null }` (parallel multi-read; unreadable -> `null` + Warning)
  - `await fs.write(path, content, { eol?: "lf" | "crlf" })` (default keeps the file's style; new `.bat`/`.cmd` -> CRLF) · `fs.exists(path)` (sync boolean) · `await fs.bytes(path, { offset?, length? })` -> `Buffer` (negative offset = from end; `<=2MB`) · `await fs.hash(path, algo?)` -> hex string (streams any size; `sha256` default, also `sha512`/`sha1`/`md5`) · `await fs.stat(path)` · `await fs.list(path)` -> `string[]`; `{ detail: true }` -> `[{ name, isDir, size }]` (dir names end with `/` in both) · `await fs.tree(path, depth?)`
  - `await fs.mkdir(path)` (-p) · `await fs.rm(path, { force? })` (file/empty dir) · `await fs.rename(from, to)` (`mv`) · `await fs.cp(from, to, { recursive? })` — immediate, not transactional
- **`edit` (default) & `tx` (opt-in rollback)**:
  - **Choose the lowest-token edit mode** (avoid echoing 20+ lines in `target`): **1) Whole function/method/struct** -> `await edit.replaceSymbol(path, "Type::method", P.newFn)` (or hunk `{ symbol, replaceSymbol: true, replacement }` — **0 `target` tokens**, auto-keeps leading doc comments/decorators unless `P.newFn` includes them); **2) 10–120 line block** -> `{ symbol?, target: "<start line>", endTarget: "<end line>", replacement: P.newBlock }` (replaces closed span `[target .. endTarget]`); **3) 1–5 line tweak** -> `{ symbol: "Type::method", target, replacement }`.
  - `await edit.apply({ edits: [{ path, hunks: [{ target, endTarget?, replacement, symbol?, replaceSymbol?, nth?, startLine?, endLine?, replaceAll? }], create?, overwrite? }], dryRun?, bestEffort?, verify? })` -> `{ ok, applied, failures? }` · shortcuts: `await edit.replace(path, target, replacement, { symbol?, endTarget?, nth?, replaceAll? })` · `await edit.replaceSymbol(path, symbol, replacement)`
  - **Default for all edits (including creating new files alongside edits)**: pass every file to one `edit.apply` (new files go in the same `edits` array via `{ path, create: P.newFile, overwrite: true }`; every hunk across all files is validated before any write, so one bad hunk writes nothing, or set `bestEffort: true` to write matching files and list the rest in `failures`), then run `sh.checks`. **If a check fails, keep the edits** and send only the fix next turn — never resend the whole payload.
  - `const t = await tx.begin(); await t.edit([{ path, hunks }]); const v = await t.verify(["go vet ./...", "go test ./pkg/..."]); if (!v.ok) { await t.rollback(); return v.failures; } await t.commit();` — **only when a failed check must leave the tree untouched**: rollback discards every edit, so a retry resends them all (uncommitted `tx` auto-rolls back; also `t.replaceSymbol(path, "Fn", P.newFn)`, `t.write(path, content)`, `t.rm(path)`, `t.rename(from, to)`, `await t.diff()`, `await t.status()`)
- **`git` & `sh`**:
  - `await git.status(repoDir?)` -> `{ isRepo, branch, clean, staged, modified, untracked }` · `await git.diff({ staged?, stat?, nameOnly?, ref?, path? })` -> `string` · `await git.log({ n?, grep?, since?, author?, format?, path? })` -> `string` (string args also work) · `await git.show({ ref?, stat?, nameOnly? })` -> `string` · `await git.blame(path, { cwd?, startLine?, endLine? })` -> `string` · `await git.query("rev-parse HEAD")` -> `string` (read-only subcommands incl. `worktree list`, `stash list`)
  - `await sh.exec(cmd, { cwd?, env?, shell?: "pwsh" | "cmd" | "bash" | "sh", timeoutMs?, compact?: true })` -> `{ ok, exitCode, timedOut, output, durationMs }` (non-zero exit returns `ok: false`; pass `throwOnError: true` to throw `CmdFailed`; default `15s` timeout + process-tree kill; `sh.shell` = default dialect; `compact` keeps only summary/failure lines, so never use it when you need the output; `truncated` = bytes cut from the middle)
  - `await sh.run(file, args?, { cwd?, env?, stdin?, timeoutMs? })` -> `{ ok, exitCode, timedOut, stdout, stderr, durationMs }` (no shell: no quoting issues; use for parseable output)
  - `await sh.checks(["go vet ./...", "go test ./pkg/..."], { cwd?, concurrency?, timeoutSec?, compact?: true })` -> `{ ok, summary, results: [{ name, command, cwd?, ok, exitCode, timedOut, durationMs, output }], failures? }` (items also accept `{ cmd, cwd?, name?, timeoutMs? }` for multi-repo checks; same shape for `t.verify`)
- **Standard Utility Globals**: `Buffer` (`utf8`/`base64`/`base64url`/`hex`/`utf16le`), `btoa`/`atob`, `TextEncoder`/`TextDecoder`, `path` (`join`/`resolve`/`dirname`/`basename`/`extname`), `crypto` (`randomUUID`/`createHash`), `URL`/`URLSearchParams`, `setTimeout`/`clearTimeout`, `structuredClone`, `await sleep(ms)`, read-only `process` (`platform`, `arch`, `env` with secret-looking values redacted, `cwd()`) and `os` (`homedir()`, `tmpdir()`, `EOL`) are available globally without `import`.
- **`state` & External `mcp` / `tools`**:
  - `state.set(key, val)` / `state.get(key)` / `state.keys()` / `state.delete(key)` / `state.clear()` — persists across turns; `print(state.page(key, n))` (or `state.page(n)` for latest) shows page `n` (`-1` = last); oversized outputs auto-save in memory to `state.get("__result_N")` (prefer the explicit `__result_N` key under concurrency; `"__last_result"` aliases the latest spill).
  - `await tools.search("query")` -> `await mcp.<server>.<tool>(args)` -> `{ text, data? }` (`res.data` holds auto-parsed JSON or `structuredContent` when JSON; `await tools.describe(ref)` shows input schema).
- **Errors**: `e.name` is `NotFound` | `NoMatch` | `Ambiguous` | `NeedsApproval` | `Denied` | `Timeout` | `BadArgs` | `CmdFailed` | `Error`; `e.message` = `"op: detail"`; `e.data` holds details (e.g. `Ambiguous` -> `{ lines, symbols }`). Capped results (`search.rg`, `fs.list`, ...) are reported under `Warnings:`.

## Hygiene

0. **Reading whole files → native `read_file`** (46 KB each, parallel calls don't share a budget). PTC output is capped at 9.6 KB (Antigravity spills larger MCP output to `output.txt`, so don't raise `maxOutputBytes` past it): use PTC to locate and return only what you need (`ast.read(path, symbol)`, `fs.read` line ranges, `search.rg({ count: true })` for totals). Long text is paged: `print(state.page('__result_1', 2))` (or `state.page(2)` for latest).
1. **Fast PTC + Async `/tasks` Relay**: When making code changes followed by a heavy `>15s` test/build suite, run edits + fast compile/vet inside `mcp_agy-ptc_vm_exec` first, then launch the heavy suite via built-in `run_command(WaitMsBeforeAsync: 500..2000)` so `/tasks` streams live logs and wakes you when done. Never use `run_command` for `rg`/`grep`/`find`/`git status` or `<15s` checks.
2. **Return compact, unescaped output (`<= 9.6 KB`)**: Filter, count, and project inside TypeScript. For multiline code snippets, diffs, logs, or reports, prefer `print(...)` / `console.log(...)` (without `return`) or returning a plain formatted `string` to avoid JSON escaping overhead (`\n`, `\"`, `\\`). Use `return { ... }` for compact structured metadata or objects you want saved in `state.get("__last_result")`; pass `maxOutputBytes` only when larger raw text is explicitly needed.
3. **Parallelize independent calls**: Use `await Promise.all([search.rg(...), git.status()])` inside `code`.
4. **Consult `/ptc-exec` on edge cases**: Load the `ptc-exec` skill only if you hit an unfamiliar capability error or complex external MCP bridge workflow.
5. **`NeedsApproval` means escalate, not retry**: Recursive force deletes (`rm -rf`, `Remove-Item -Recurse -Force`), `git push` / `reset --hard` / `clean -f` / `checkout -- .`, publish commands, credential paths, and writes to agent/MCP configs or shell startup files are never run in the sandbox. Do not rephrase the command to slip past the guard; re-issue it via built-in `run_command` / `edit_file` so the user can confirm.
6. **When using opt-in `tx`, always `await t.commit()`**: An uncommitted `tx` is auto-rolled back when the program ends, and the response shows it under `Warnings:`. If a warning says `ROLLBACK FAILED`, inspect the listed files before doing anything else.
